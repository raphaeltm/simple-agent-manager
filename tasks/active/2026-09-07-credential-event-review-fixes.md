## Required fixes and evidence

- [x] **Credential audience:** Personal credential events currently enter unrestricted project matching. Another project member can subscribe to `sam.credential_limit` and receive utilization, reset time, credential reference and session IDs. Enforce the existing personal-versus-shared resource boundary using server-derived visibility, at matching and every read/delivery boundary. Shared-project credentials remain usable by project members; personal credentials remain user-scoped. Test two distinct users in one project, an unrelated project, and authorized affected-session delivery. Future catalog/history and standing-watch consumers must apply the same restriction; filtering only the first match path is insufficient.
- [x] **Telemetry origin:** Go recursively searches arbitrary `SessionNotification` data for `_claude/rateLimit`, so tool input/output can forge provider telemetry. The pinned ACP Go SDK supports typed `UsageUpdate`. Read only the actual adapter-owned usage metadata variant. Test real wire decoding through `SessionUpdate` and the authenticated callback, plus malicious tool metadata that produces no observation.
- [x] **Provider reset units:** Claude's numeric `resetsAt` is epoch seconds, but the new parser casts it directly to milliseconds. Verify the pinned upstream adapter contract and convert at that boundary. Test numeric real-wire fixtures, not only an ISO string the SDK does not emit.
- [x] **Bounded reporting lifecycle:** The Go callback launches one goroutine per notification, with unordered background-context retries and no final drain in `Stop`. Use a bounded serialized reporter, safe coalescing, cancellation-aware retries and a finite shutdown flush before idle/teardown. Test bounded concurrency, ordering, retry exhaustion, cancellation and final observation delivery. It must not pin compute indefinitely.
- [x] **Observation time:** Callback times are only checked for nonnegative values. A far-future sample suppresses later legitimate observations; old first samples are admitted, and client-derived `receivedAt` can affect subscription timing. Capture server receipt time, validate safe timestamp range and configurable maximum age/future skew before writes, and retain source time as evidence. Test future poisoning, expired first samples, equal-time conflicts and normal out-of-order arrival.
- [x] **Unknown remains unknown:** `computeLevel` maps unknown status with no utilization to `ok`, causing a later reset-only or limit-only header to clear a rejection. Do not lower severity or emit reset without affirmative recovery evidence. Test rejected/critical followed by partial and unsupported telemetry, then a real recovery.
- [x] **Atomic transitions and durable admission:** The current read-window → compute edge → admit-to-DO → upsert-window sequence races concurrent observations and can lose its state checkpoint after admission. Delivery identity uses transition/reset/source while its fingerprint includes changing observation metadata; repeated same-window crossings can conflict. Admission outcomes are ignored. Independent Cloudflare review exercised the actual producer with dynamic boundary stubs: warning → reset → warning in one reset window reports three admissions although the third conflicts; a delayed older reset is emitted after a newer critical observation despite the final D1 CAS; admission followed by D1 failure causes the next warning to conflict while reporting success. Establish an atomic conditional transition plus immutable emission intent, with stable payload and identity across retries, then recover cross-store admission. Handle conflict/capacity outcomes truthfully. Compose with slice B's source-recovery mechanism where appropriate, without a second generic queue. Prove these three failure sequences and first-admission recovery with real D1 plus canonical ProjectData admission; stubs alone are insufficient final evidence.
- [x] **Bounded input and storage:** Callback `rateLimits` has no array cap, and arbitrary provider/source/window identifiers can create unlimited persistent state even without an event. Allowlist supported adapter identifiers, cap body/array sizes and apply authenticated bounded admission. Add indexed finite retention/reclamation and bounds for both state and retry records, with shared defaults and overrides. Test oversized and unsupported batches, bounded maintenance and production-shaped seek behavior.
- [x] **Preserve successful inference:** Proxy attribution persistence is awaited after upstream success outside the best-effort boundary. Its D1 exception turns a paid successful request into a 502 and skips token accounting. Either establish required attribution safely before the billable request or isolate advisory telemetry persistence failures without weakening identity checks. Test successful streaming forwarding/accounting when telemetry persistence fails.
- [x] **Preserve Anthropic error evidence:** The translated Anthropic error response drops rate-limit and `Retry-After` headers before telemetry extraction. Preserve the same allowlisted headers used by other paths. Verify token-window 429 extraction and reset evidence through the actual translated route.
- [x] **Credential rotation:** Confirmed by executing the actual UPDATE SQL against SQLite: a delayed proxy response for credential A overwrites a newer injected boot credential B, and valid B callbacks then fail with `Credential attribution mismatch`. Proxy observations already retain per-request A; they must not overwrite boot fields used to verify direct ACP callbacks. Keep injected credentials bound to their runtime generation. Test overlapping old/new proxy responses and delayed ACP callbacks. Timestamp ordering alone cannot fix these different identity lifetimes.
- [x] **Structure and documentation:** Split the 916-line service into cohesive modules; do not add a file-size exemption. Update canonical API/environment/deployment documentation for new supported paths, unknown cases, bounds and configuration. Keep token analytics and cross-account routing outside this feature.

- Credential audience now uses credential-event visibility at matching, event read, subscription event list, and delivery ack/read boundaries. Personal credential events require the affected user plus affected session/chat target; shared project/platform credentials remain project-scoped. Regression coverage includes two users in one project, unrelated-project subscriptions, authorized affected-session delivery, and historical bad-match read/list/ack blocking.
- Go VM-agent telemetry now reads only typed `SessionNotification.Update.UsageUpdate.Meta["_claude/rateLimit"]`. Recursive arbitrary notification scanning was removed. Regression coverage includes real ACP wire JSON decoding into `SessionUpdate`, malicious non-usage metadata that produces no observation, and numeric Claude `resetsAt` seconds converted to epoch milliseconds.

- API observation handling now captures server receipt time, enforces configurable max-age/future-skew/reset-future bounds, allowlists provider/source/window identifiers, caps callback arrays, and does not reset severity from unknown/partial samples without affirmative recovery evidence.
- Credential-limit event admission now captures the conditional D1 state transition plus immutable admission envelope before ProjectData side effects. Retries dispatch the stored envelope and report `created`, `duplicate_replay`, `conflict`, `capacity`, `failed`, or `superseded` truthfully. Older failed reset/critical admissions are superseded if the current D1 window has advanced to a newer delivery key before retry.

Allowlisted Anthropic/OpenAI rate-limit headers and `Retry-After` are copied through translated error responses.
