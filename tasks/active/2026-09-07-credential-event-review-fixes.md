## Required fixes and evidence

- [ ] **Credential audience:** Personal credential events currently enter unrestricted project matching. Another project member can subscribe to `sam.credential_limit` and receive utilization, reset time, credential reference and session IDs. Enforce the existing personal-versus-shared resource boundary using server-derived visibility, at matching and every read/delivery boundary. Shared-project credentials remain usable by project members; personal credentials remain user-scoped. Test two distinct users in one project, an unrelated project, and authorized affected-session delivery. Future catalog/history and standing-watch consumers must apply the same restriction; filtering only the first match path is insufficient.
- [ ] **Telemetry origin:** Go recursively searches arbitrary `SessionNotification` data for `_claude/rateLimit`, so tool input/output can forge provider telemetry. The pinned ACP Go SDK supports typed `UsageUpdate`. Read only the actual adapter-owned usage metadata variant. Test real wire decoding through `SessionUpdate` and the authenticated callback, plus malicious tool metadata that produces no observation.
- [ ] **Provider reset units:** Claude's numeric `resetsAt` is epoch seconds, but the new parser casts it directly to milliseconds. Verify the pinned upstream adapter contract and convert at that boundary. Test numeric real-wire fixtures, not only an ISO string the SDK does not emit.
- [ ] **Bounded reporting lifecycle:** The Go callback launches one goroutine per notification, with unordered background-context retries and no final drain in `Stop`. Use a bounded serialized reporter, safe coalescing, cancellation-aware retries and a finite shutdown flush before idle/teardown. Test bounded concurrency, ordering, retry exhaustion, cancellation and final observation delivery. It must not pin compute indefinitely.
- [ ] **Observation time:** Callback times are only checked for nonnegative values. A far-future sample suppresses later legitimate observations; old first samples are admitted, and client-derived `receivedAt` can affect subscription timing. Capture server receipt time, validate safe timestamp range and configurable maximum age/future skew before writes, and retain source time as evidence. Test future poisoning, expired first samples, equal-time conflicts and normal out-of-order arrival.
- [ ] **Unknown remains unknown:** `computeLevel` maps unknown status with no utilization to `ok`, causing a later reset-only or limit-only header to clear a rejection. Do not lower severity or emit reset without affirmative recovery evidence. Test rejected/critical followed by partial and unsupported telemetry, then a real recovery.
- [ ] **Atomic transitions and durable admission:** The current read-window → compute edge → admit-to-DO → upsert-window sequence races concurrent observations and can lose its state checkpoint after admission. Delivery identity uses transition/reset/source while its fingerprint includes changing observation metadata; repeated same-window crossings can conflict. Admission outcomes are ignored. Independent Cloudflare review exercised the actual producer with dynamic boundary stubs: warning → reset → warning in one reset window reports three admissions although the third conflicts; a delayed older reset is emitted after a newer critical observation despite the final D1 CAS; admission followed by D1 failure causes the next warning to conflict while reporting success. Establish an atomic conditional transition plus immutable emission intent, with stable payload and identity across retries, then recover cross-store admission. Handle conflict/capacity outcomes truthfully. Compose with slice B's source-recovery mechanism where appropriate, without a second generic queue. Prove these three failure sequences and first-admission recovery with real D1 plus canonical ProjectData admission; stubs alone are insufficient final evidence.
- [ ] **Bounded input and storage:** Callback `rateLimits` has no array cap, and arbitrary provider/source/window identifiers can create unlimited persistent state even without an event. Allowlist supported adapter identifiers, cap body/array sizes and apply authenticated bounded admission. Add indexed finite retention/reclamation and bounds for both state and retry records, with shared defaults and overrides. Test oversized and unsupported batches, bounded maintenance and production-shaped seek behavior.
- [ ] **Preserve successful inference:** Proxy attribution persistence is awaited after upstream success outside the best-effort boundary. Its D1 exception turns a paid successful request into a 502 and skips token accounting. Either establish required attribution safely before the billable request or isolate advisory telemetry persistence failures without weakening identity checks. Test successful streaming forwarding/accounting when telemetry persistence fails.
- [ ] **Preserve Anthropic error evidence:** The translated Anthropic error response drops rate-limit and `Retry-After` headers before telemetry extraction. Preserve the same allowlisted headers used by other paths. Verify token-window 429 extraction and reset evidence through the actual translated route.
- [ ] **Credential rotation:** Confirmed by executing the actual UPDATE SQL against SQLite: a delayed proxy response for credential A overwrites a newer injected boot credential B, and valid B callbacks then fail with `Credential attribution mismatch`. Proxy observations already retain per-request A; they must not overwrite boot fields used to verify direct ACP callbacks. Keep injected credentials bound to their runtime generation. Test overlapping old/new proxy responses and delayed ACP callbacks. Timestamp ordering alone cannot fix these different identity lifetimes.
- [ ] **Structure and documentation:** Split the 916-line service into cohesive modules; do not add a file-size exemption. Update canonical API/environment/deployment documentation for new supported paths, unknown cases, bounds and configuration. Keep token analytics and cross-account routing outside this feature.
