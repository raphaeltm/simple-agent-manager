## Required fixes and evidence

- [ ] **Only the winning task transition emits.** `transitionTaskToTerminal` batches a guarded task update with an unconditional source-intent insertion. Executing the actual SQL with migration 0144 against a cancelled task produced task updates 0, status inserts 0, outbox inserts 1 for `task.failed`. Use a unique per-invocation proof of the winning transition to condition both status and outbox insertion atomically. Timestamp equality alone is not ownership. Prove cancellation, same-millisecond competing transitions, recovery supersession and workspace/session ownership races with a barrier between initial read and batch; the loser must persist no status or source event.
- [ ] **Fence every claim completion.** Outbox processing leases have no ownership generation. Actual SQL showed a late failure from attempt 1 clearing attempt 2's replacement lease. Return a unique claim token/generation and require it on all success, retry, permanent-failure and malformed-payload writes. Check affected rows and report the actual persisted result after losing ownership. Test late success/failure before and after replacement completion, including expired leases and lost acknowledgement.
- [ ] **Immutable identity and truthful conflicts.** Duplicate delivery inserts ignore fingerprints, and canonical `conflict` is stored as `admitted`. Actual-function tests reproduced both. Compare the persisted immutable identity and incoming envelope, retain the original retry envelope, and expose conflict as a terminal unsuccessful outcome. Avoid modifying an already-admitted original event merely because a second local enqueue reused its key incorrectly. A normal terminal hook currently rebuilds a poorer envelope than the transaction (missing `fromStatus`, workspace/session and actor metadata); have it nudge the already-persisted intent by ID instead. Test normal terminal admission as well as conflicting reuse and canonical conflict.
- [ ] **Finite indexed expiry and retention.** The recovery selector excludes expired rows forever. Pending, processing and retryable rows can remain nonterminal; all terminal rows also accumulate. The actual due query over 1,000 versus 20,000 expired pending rows used 5,045 versus 100,045 SQLite VM instructions while returning zero results. Add separately bounded indexed expiry/exhaustion terminalization, due and expired-lease candidates, and terminal-row reclamation. Avoid whole-backlog sorting and residual scans. Define a finite dedup/audit retention horizon and preserve immutable replay guarantees within it. Use a shared mutation/row budget and a configured wall budget; prove a second sweep is quiet and historical depth does not increase candidate scan work.
- [ ] **Enforce attempts at claim time.** A pending intent already at 8/8 attempts was successfully claimed as attempt 9. Put the ceiling in the atomic claim predicate, and terminalize abandoned exhausted leases. Test repeated crashes with no completion callback as well as caught failures.
- [ ] **Fresh time and bounded external admission.** Recovery reuses one sweep timestamp for every sequential claim and has no wall deadline. A slow first admission can leave later claims born expired or admit after TTL. Resolve current time for each claim/settlement, impose configured sweep and admission deadlines, and preserve fenced recoverable state after timeout or ambiguous acknowledgement. Do not suggest a JavaScript timeout cancels a remote side effect. Prove the next cron phases still run and a later sweep converges once.
- [ ] **Safe canonical webhook facts.** `generic-webhook-project-event-producer.ts` copies arbitrary body/headers into a second durable event/outbox surface with a secret-key regex that misses `clientSecret`, `privateKey`, plural `credentials`, `authToken`, and cookie/session-like fields. Memory-only actual-function probes retained the seeded canary values and canonical normalization accepted them. Use a small allowlisted fact envelope and/or the established deterministic redaction boundary; unknown free-form payload values must not silently become broadly available event metadata. Keep authenticated trigger execution's existing intended payload contract separate from the new event projection. Test realistic nested camel/snake/kebab case credentials, raw bearer/key strings and headers; canaries must be absent from event rows, outbox payloads, logs and read/delivery outputs.
- [ ] **One aggregate metadata budget.** Producer truncation is per-object/per-string but canonical admission limits total keys, total bytes and depth including wrappers. Actual producer plus canonical normalization rejects a 591-byte body with 50 keys, a 10,341-byte body, a four-level 27-byte object, and a blank JSON key. Produce metadata that meets configured canonical bounds before persisting an intent, reserve wrapper overhead, handle multibyte values and normalized-key collisions deterministically, and provide truthful truncation/outcome evidence. Valid authenticated requests must not create permanently impossible retry intents. Test through real canonical admission, not only a mocked enqueue.
- [ ] **Setup parity.** The deployment GitHub manifest adds CI/review permissions and subscriptions, but `apps/www/src/components/GitHubAppSetup.astro` still generates only `pull_requests` and `push`/`pull_request`. Align all supported app creation/setup paths and upgrade guidance. Test the actual generated public setup URL and deploy manifest for parity. This is a functional URL/config fix; preserve the visible layout and coordinate any visual evidence needed with the parent final UI sweep.
- [ ] **Native CI correlation.** `check_run` metadata omits its native `pull_requests` array; the current fixture's synthetic top-level `pull_request` does not prove real GitHub correlation. Preserve bounded native PR references along with repository, commit SHA, run/suite IDs and attempts. Use provider-shaped check-run/check-suite/workflow-run fixtures; two results for old/new commits remain distinguishable.
- [ ] **Config, structure and documentation.** Add shared defaults, validated overrides, canonical env/setup/docs mappings and bounded outcome metrics for new limits. Keep files below the repository size gate without exemptions. Append a new D1 migration if needed; do not edit migrations already integrated by siblings. No ProjectData schema changes in this slice.
