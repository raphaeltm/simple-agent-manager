# Ship Glasshouse A2 homepage + shared glass components

## Problem

Raphaël reviewed the Glasshouse homepage prototypes (SAM idea `01M4XZVMKCCAK7C21Z8V55K18K`)
and asked (2026-10-14): "I like a2. Make it so. Ship to prod. Make sure the rest of the page is
consistent as well. Make sure you create components that we can reuse across the site and app
where applicable as well. Ship it."

A2 = prototype A (real SAM UI layers in an exploded 3D stack that assembles, chat transcript
streams in, amber "needs input" then green "task completed") on top of the existing square
node/workspace network redrawn as a **glass floor in perspective**. Prototype source: SAM
Library file `01M4Y49RHE90WTY6CTN9JAQ3Z5` (`variant-a2.html?bg=floor`, `glassgrid.js`).

Also fold in the live bugs from idea `01M4XZQRYJ38CMN7R2PKMS370N`:
1. Dark mode shows every themed screenshot twice (dark + light stacked) on `/`, `/features/`,
   `/enterprise/cost-control/` — `.shot-light { display:none }` (0,1,0) loses to component rules
   `.x:where(.astro-…) :global(picture) { display:block }` (0,1,1).
2. `NodeGrid.astro` keeps animating under `prefers-reduced-motion` and while offscreen; it is
   1,370 of the homepage's 2,044 DOM elements.

## Research findings

- Homepage: `apps/www/src/pages/index.astro` composes Header, Hero (+NodeGrid), SocialProof,
  FeatureShowcase, HowItWorks, Comparison, Roadmap, CtaFooter. Header/CtaFooter are used by ~20
  pages (features, enterprise, compare, integrations, presentations, self-host, blog layouts);
  `--header-height: 64px` is relied on by `self-host/index.astro`, `BlogPost.astro`,
  `blog/index.astro`.
- Tokens: `apps/www/src/styles/global.css` (www: `--color-*`, `--glass-*`, theme via
  `html[data-theme]`); app: `packages/ui/src/tokens/theme.css` (`--sam-*`, theme via
  `[data-ui-theme]`) + glass utilities in `apps/web/src/index.css` (`.glass-*`,
  `.glass-card-glow`, reduced-transparency/contrast fallbacks).
- Shared package: `packages/ui` (tsc build; source subpath exports already used for CSS/hooks:
  `./styles.css`, `./tokens/theme.css`, `./hooks/useModalInteraction`). Tests: vitest + jsdom
  (`packages/ui/tests/*.test.tsx`), Storybook stories. Scoped rules: 04, 17, 56, 64.
- App sign-in page `apps/web/src/pages/Landing.tsx` is the natural app reuse point (plain centered
  card on `bg-canvas`). Its unit test mocks `@simple-agent-manager/ui` with a fixed factory →
  must add the new export to the mock. Playwright `landing-audit.spec.ts` exists.
- Real-UI sources (committed, both themes): `apps/www/public/images/features/sam-hero-live-session(-light).png`
  (1920×1400), `sam-nodes-multi-provider(-light)`, `sam-comments-chat-thread(-light)`,
  `sam-notifications-feed(-light)`, `sam-compute-placement-decision(-light)`. Generated by
  `apps/web/tests/playwright/marketing-shots-*.spec.ts` (Northwind fixture, `MARKETING_THEME`).
- The prototype phone used `docs/chat-permission-request-mobile.png` (acme fixture, dark only).
  Raphaël's standing rule (task `2026-09-14-marketing-site-feature-refresh`): every UI screenshot
  must exist in light mode and show in light mode → capture a new Northwind phone shot in both
  themes from `marketing-shots-platform.spec.ts` (hero session at 390×844).
- Prior lesson (same task): SonarCloud failed on duplicated new code (shape-identical literals,
  copied spec helpers) → keep data in JSON/helpers, no copy-paste between specs.
- CI: `ci.yml` filter `marketing-site` = `apps/www/**`; `web-ui` includes `packages/ui/**`.
  `deploy-www.yml` deploys only on `apps/www/**` changes → shared glass sources under
  `packages/ui/src/glass/**` must be added to both filters, or future shared changes won't
  rebuild/redeploy the site.
- Staging: no staging pipeline for www (www.sammy.party is a stale manual copy). App staging via
  `deploy-staging.yml` covers the Landing change. www verification = production build +
  `astro preview` + Playwright (static site), then post-deploy check on the live site.
- Typecheck for www is an `astro check` error-baseline ratchet (`scripts/quality/check-astro-templates.ts`).

## Implementation checklist

### Shared (packages/ui)
- [ ] `src/glass/node-field.ts`: framework-agnostic glass node field (floor + flat modes), typed;
      own canvases; dark/light/auto theme (www `data-theme`, app `data-ui-theme`); 30 fps cap;
      pause offscreen/hidden; ResizeObserver; reduced motion = static frame; safe no-op when canvas
      2D context is unavailable; story API (`nodeNear`, `wakeNear`, `pin`, `burst`, `pause/resume`,
      `destroy`); pure helpers exported for tests (projection, node build, PRNG)
