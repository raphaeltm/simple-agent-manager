## Research findings

- Hero motion language (`src/components/hero/*`): real-UI crops of committed captures, themed
  CSS backgrounds (`--img-dark`/`--img-light`, only the active theme downloads), glass planes
  (`.sam-glass .sam-glass-rim .sam-glass-sheen`), chips at depth (`translateZ`), light with a
  source (green = working, amber = needs input), exploded → assembled pose, finite story that
  rests on its final frame, final frame is the no-JS / reduced-motion markup, pointer tilt on fine
  pointers, pause control (`hero-motion.ts`).
- Source captures exist in both themes for every layer needed (`public/images/features/*.png`,
  generated by `apps/web/tests/playwright/marketing-shots-*.spec.ts`, Northwind fixture). No
  feature section has a mobile capture; phone legibility must come from tighter crops.
- Feature screenshots are `<img loading="lazy">`; CSS backgrounds are not lazy, so scene layers
  must be gated until a scene approaches the viewport (with a `<noscript>` fallback).
- WCAG 2.2.2: auto-playing motion that lasts more than 5 s needs a pause control. Keeping every
  section story under 5 s (plays once, rests) avoids extra controls; the hero's existing pause
  control should also stop section stories.
- Prior lesson (PR #2348 task): SonarCloud flagged duplicated new code → keep per-scene data as
  JSON content, one generic renderer, shared helpers between build scripts.
- www has no staging (`deploy-www.yml` deploys production only); verification = local production
  build + `astro preview` + Playwright. Narrow marketing CI (policy 8afaafbb).

## Design

One generic, data-driven scene per feature section:

- **Scene data** (`src/data/scenes/<slug>.json`): crops (source-pixel boxes) for a main window and
  1-2 floating chips, tiles (regions that appear in turn), rings (mint/amber/green highlight that
  outlines a real UI element, optionally moving between elements), lights, an optional state swap
  (crossfade to a second real capture), per-layout placement (wide / narrow via container query),
  beats (step timing), caption and accessible description.
- **Build** (`scripts/build-feature-scenes.ts`, sharing helpers with `build-hero-layers.ts`): crops
  both themes into `public/images/scenes/*.webp` and writes `src/data/feature-scenes.json`; tile
  regions are blanked in the base image so they can appear.
- **Render** (`src/components/scenes/FeatureScene.astro`): glass window + chips in a 3D stage, lit
  floor; resting markup is the final frame.
- **Motion** (`src/components/scenes/scene-motion.ts`): loads layers near the viewport, plays the
  story once when the scene is in view (exploded → assembled, then steps), honours reduced motion
  and the hero pause control, pointer tilt on fine pointers.

## Implementation notes

- Blank tiles: a single stretched background row turned the app's grain and radial glows into
  stripes; the fill is now a per-column median of 5 rows above and below each band, box-blurred
  horizontally and blended vertically (`build-feature-scenes.ts` `blank`).
- Dev-server gotcha: deleting and recreating `public/images/scenes/` made the Astro/Vite dev server
  404 every new file until restart; the build script now removes only stale files.
- Perspective enlarges chips that float in front of the window (depth × spread), so chips keep to
  96% of the stage width and narrow stages scale depth by 0.5; the layout test measures it.
- Story start uses a middle-of-viewport band (`rootMargin: -30% 0 -30% 0`), not a visibility
  ratio: a scene taller than the screen could never reach a ratio and would wait in its intro.
- Tests drive a paused Playwright clock and wait for the IntersectionObserver-driven start before
  stepping; `scrollIntoView` must be `behavior: 'instant'` because the page scrolls smoothly.
- Measured on 62087e100 (same script, decoded bytes; baseline = live production www): desktop
  load 1,007 → 782 KB, full scroll 1,344 → 1,129 KB; phone load 842 → 652 KB, full scroll
  1,245 → 1,030 KB; DOM 694 → 778; page height desktop 14,334 → 15,061 px, phone
  18,651 → 19,980 px (scenes are taller than the old screenshots, and now legible). JavaScript
  (gzip): scene chunk 1.4 KB plus shared motion chunk 0.5 KB, hero chunk 7.2 → 7.1 KB; net about
  +1.8 KB.

## Acceptance criteria

- Every homepage feature section shows an animated real-UI preview (no static screenshot left).
- Previews use the hero's glass material, light and motion language, in both themes.
- Reduced motion and no-JS show a complete static final frame; motion ≤ 5 s per scene; hero pause
  stops them.
- Phone and desktop layouts are legible and nothing is cut off; no horizontal overflow.
- Only the active theme's layers download, and only near the viewport.
- Copy unchanged; hero unchanged (its tests still pass).
