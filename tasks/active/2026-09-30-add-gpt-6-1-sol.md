# Add GPT-6.1 Sol

## Problem

OpenAI released GPT-6.1 Sol on 2026-09-29. SAM's static OpenAI Codex picker, OpenCode fallback catalog, and platform AI proxy registry do not yet list `gpt-6.1-sol`, so users can miss the model when dynamic discovery is unavailable and the platform proxy rejects it as unknown.

## Research findings

- OpenAI's model page identifies the API model as `gpt-6.1-sol`, with a 1,050,000-token context window, 128,000 maximum output tokens, and standard pricing of $2 input / $10 output per million tokens.
- OpenAI Codex's authoritative `models.json` lists `gpt-6.1-sol` with `minimal_client_version: 0.153.0`. SAM already pins Codex CLI `0.156.1`, so the Codex CLI and `codex-acp` wrapper do not need a version change for model compatibility.
- `@agentclientprotocol/codex-acp` 2.x contains unrelated breaking AIR tool-call and diff-report changes. Bundling that upgrade into this model-catalog change would require a separate ACP regression effort.
- Cloudflare AI Gateway supports OpenAI's Responses API, and OpenAI documents Responses API tool calling for GPT-6.1 Sol. SAM's existing OpenAI proxy dispatch is model-registry driven, so adding the platform model entry is the required code change.
- GPT-6.1 Sol supports Chat Completions without tools, but tool calling requires the Responses API. Explicit transport metadata keeps its excellent tool capability and workspace-agent role accurate while marking it ineligible for chat-completions agent defaults; the admin endpoint omits/rejects it and the chat route directs tool-bearing requests to `/responses`.
- The live `models.dev` OpenCode Zen catalog now includes `gpt-6.1-sol`; OpenCode Go does not. SAM's static OpenCode fallback should therefore add only `opencode/gpt-6.1-sol`.
- The same live fallback comparison found one concurrent OpenCode Zen addition, `opencode/claude-sonnet-5-5`. The catalog lifecycle rule requires the checked static fallback to match the live snapshot, so this provider-qualified entry is included without changing the Claude wrapper or platform proxy registry.
- OpenAI's current deprecations page lists no newly deprecated IDs present in SAM's current OpenAI Codex picker or GPT-6 platform registry, so this change does not remove an existing model.
- Relevant implementation and tests are in `packages/shared/src/model-catalog.ts`, `packages/shared/src/constants/ai-services.ts`, `packages/shared/tests/model-catalog.test.ts`, `packages/shared/tests/unit/model-catalog-alternative-providers.test.ts`, and `packages/shared/tests/unit/ai-model-tiers.test.ts`.

## Acceptance criteria

- The OpenAI Codex static catalog lists `gpt-6.1-sol` as a current GPT-6-series model.
- The OpenCode static fallback lists `opencode/gpt-6.1-sol` and does not invent an OpenCode Go entry.
- The platform AI proxy accepts `gpt-6.1-sol` on `/responses` as a premium OpenAI model with current pricing and context metadata, while chat-completions agent defaults cannot select it.
- Focused tests prove catalog visibility, known-model validation, provider-specific fallback placement, platform tier classification, and tool-bearing `/responses` forwarding.
- Staging and production catalog responses expose the new model after successful deployments.
