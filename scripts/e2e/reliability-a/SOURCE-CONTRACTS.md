Resource statuses `recovery`, `evicted`, `deleted` from shared/types/workspace.ts are typed observations. No node DELETE is supported, including linked nodes. Unknown fields are dropped; unknown selected field values fail closed. Reads do not grant authority from inventories. The source audit adds no arbitrary endpoint or error fallback.

ACP identity at the state endpoint is UUID or ULID (project-data/acp-sessions.ts uses opts.id or types.ts generateId/crypto.randomUUID). This does not broaden task/workspace/node IDs. Idle permission additionally requires both activityAt and runtimeWorkUpdatedAt at or after this controller submit request and no future timestamp; zero/old fallback clocks remain inconclusive. Actual CLI covers UUID, ULID, null-to-UUID progression and fallback-clock refusal. Workspace DELETE pending202 never counts as confirmed cleanup; actual CLI covers both source-defined pending and confirmed responses.
